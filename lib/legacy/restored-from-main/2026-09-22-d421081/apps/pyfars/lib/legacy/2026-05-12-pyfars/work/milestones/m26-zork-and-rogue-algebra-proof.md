# M26 — Zork and Rogue Algebra Proof

If Zork and Rogue run on the predication substrate with no game engine code outside PyFARS, the algebra handles: spatial navigation, object interaction, state machines, procedural generation, inventory management, quantitative mechanics, and turn sequencing.
And if the algebra handles all that, it handles the operational ship — because the operational game is Zork (navigate the knowledge base, interact with tasks) plus Rogue (manage capability inventory, resolve dispatch conflicts, level up offices).

This is not a game product.
It is a **proof**: every mechanic that classical game engines implement with special-case code is a specialization of predication fiber composition, closure rule firing, and stratum-tagged atom settling.

## What's built

### Spatial navigation (Zork) as predication

A Zork game world is a set of predication cells in the substrate:

```
(room:dungeon-entrance, exit-north, room:throne-hall, t)
(room:dungeon-entrance, contains, item:sword, t)
(room:dungeon-entrance, description, "A mossy stone chamber.", t)
(item:sword, is-carried-by, player:1, ⊥)  -- stratum 0: sword not yet in inventory
```

Exits are morphisms in the predicate category — `exit-north` is a predicate whose fiber carries the destination room entity.
The predication-fiber-functor theorem establishes that predicate specializations, converges, and projections on these fiber algebras compose correctly via bilattice homomorphisms, so compound navigation (go north then east) is the composite of the two exit-predicate lookups.

`look` = a cl^S rule that fires against the `contains` and `description` cells at the player's `current-location` predicate, producing a stratum-1 summary cell: "what is in this room and what does it say about itself."
The summary cell settles to stratum 2 via N_Δ.

`go north` = a workitem that updates the player's `current-location` cell at stratum 0 to the room connected by `exit-north`.
The next cl^S pass fires navigation rules against the new location's fiber, producing new stratum-1 cells for the new room's contents.
N_Δ settles them to stratum 2.

`take sword` = a workitem that writes `(item:sword, is-carried-by, player:1, t)` at stratum 0.
A cl^S rule fires: if a player carries an item and the item is in a room, the item is no longer in the room.
This produces a new stratum-1 cell `(room:dungeon-entrance, contains, item:sword, f)` (denied containment).
N_Δ stabilizes both the carry cell and the denial cell to stratum 2.

The game's REPL is a thin CLI: read command → emit workitem → run one settling endofunctor pass → print stratum-2 cells for the player's current location.

### Object interaction and state machines as Belnap-Fitting FOUR values

A door's state is a predication cell valued in the Belnap-Fitting FOUR bilattice:

```
(door:iron-door, is-open, ⊥)  -- stratum 0: no information yet
```

`open door` = a workitem that writes `(door:iron-door, is-open, t)` at stratum 0.
A cl^S rule fires: if is-open is t and the door is in the player's location, the room's `exit-through` predicate for that door becomes available.
N_Δ stabilizes the is-open cell to stratum 2.

`close door` = overwrites with `(door:iron-door, is-open, f)` at stratum 0.
If a lock is engaged and close is asserted, a cl^S rule may fire to produce `(door:iron-door, is-open, ⊤)` at stratum 1 — a contradiction, surfaced as "the door resists closing" rather than silently overridden.

The bilattice's four values `{⊥, t, f, ⊤}` are not implementation choices — they are the structure of the predication fiber algebra.
State machines don't need special code; they are Belnap-Fitting FOUR value transitions on predication cells, driven by cl^S rule firings.

**Stratum visibility demonstration (acceptance criterion):** The closed door test: assert `(door:iron-door, is-open, f)` at stratum 0.
Before the settling endofunctor runs, the MCP surface returns nothing (stratum-0 atoms are below π₂).
After cl^S and N_Δ run, the MCP surface returns the stratum-2 settled value.
This demonstrates concretely that π₂ is the authoritative game state.

### Inventory as predication

Inventory is containment predication: `(entity:player, carries, item:lantern, t)` and `(item:lantern, is-lit, t)`.
Inventory weight is a fold catamorphism over the player's `carries` cell-set: the predication-cell-as-fold-source theorem establishes that there exists a unique bilattice-valued fold `fold_⊙` over the carries-cell-set that returns the ∨_k-join of the carried items' weight cells.
This is the unique catamorphism on the cell-list by Lambek's theorem — there is no need to write a weight-summing loop separately.

Inventory capacity limits are cl^S rules: if the player's carries-cell-set fold exceeds the capacity cell's value, a new stratum-1 cell `(player:1, carrying-is-overloaded, ⊤)` is produced.
Overload mechanics emerge from the rule system, not from special code.

### Rogue: procedural generation as closure cascade

A Rogue dungeon template is a predication cell-set:

```
(room-template:basic-square, has-exit-count, 4)
(room-template:basic-square, spawns-monsters, t)
```

A dungeon-generation closure rule fires against the template cell-set and the current dungeon's empty coordinate grid, producing new stratum-1 cells:

```
(room:coord-3-4, instance-of, room-template:basic-square)
(room:coord-3-4, exit-north, room:coord-3-5)
(room:coord-3-4, exit-south, room:coord-3-3)
...
```

N_Δ stabilizes these to stratum 2.
The new stratum-2 room cells satisfy further cl^S rule premises (monster-spawn rules, item-placement rules), causing the outer alternation to continue.
The dungeon grows by closure cascade — what settled at stratum 2 in step N enables stratum-1 firings in step N+1.

The predication-cell-as-fold-source theorem grounds each fold-step's uniqueness (e.g., the total corridor-length fold over the dungeon's room cell-set).
The four-regime-dichotomy classifies whether the dungeon-generation rule set is in the strict regime (terminates at ω₀, guaranteed for quantifier-free antecedent rules) or a transfinite regime (for rules with universal quantifiers over unbounded room sets).
A finite dungeon template with finitely many rooms is strict-regime; the settling-convergence theorem guarantees termination.

### Rogue: combat as fiber composition

Combat is predication fiber composition under the knowledge order ∨_k.
The attacker's attack cell and the defender's defense cell are composed:

```
attacker: (player:1, attack-value, 5)
defender: (monster:orc, defense-value, 2)
```

A cl^S rule fires: if attack-value ∨_k defense-value > 0 (after the subtraction is expressed as a truth-order operation on the quantale-graded values), produce `(monster:orc, hp, current-hp ∧_t damage-taken)`.
N_Δ stabilizes the HP cell.
Quantitative mechanics (HP, damage, defense) are numerical predicates on entities; the arithmetic is closure-rule-expressed bilattice operations.

The four-regime-dichotomy determines when the combat resolution terminates.
For finite-valued HP cells with Scott-continuous arithmetic rules, the settling-convergence theorem guarantees termination at ω₀ (strict regime).
For rules with universal quantifiers (e.g., "the orc rages if all allies are dead"), the regime classification is non-trivial; M26 uses only Scott-continuous combat rules to stay in the strict regime and demonstrate clean termination.

### Turn sequencing as settling endofunctor pass

A game turn is exactly one application of the settling endofunctor F_U: run cl^S until no new stratum-1 atoms are produced, then run N_Δ per-cell until joint fixed point, with outer alternation until H*_t.
The state visible to the player after a turn is the stratum-2 projection π₂ of the current fiber.

Between turns the substrate's state is the stratified predication fiber A^♭_p with all strata in place.
A player action writes new stratum-0 atoms, which trigger the next turn's F_U pass.
There is no game loop separate from the substrate's settlement loop — the game turn IS the settling endofunctor pass.

This is the key architectural claim: **the game engine IS the substrate**.
No code outside the PyFARS runtime implements game logic.
Spatial navigation, state machines, inventory, combat, procedural generation, and turn sequencing are all expressed as predication cells and closure rules, settled by the substrate's two-pass settlement engine.

## What M26 does NOT claim

- **Not a complete game product.** The Zork and Rogue implementations are proof-of-concept under `examples/zork/` and `examples/rogue/`.
  They are not shippable games.
- **Not arbitrary gameplay.** M26 demonstrates the algebra handles the mechanics listed above.
  Mechanics that require non-monotonic retraction (changing the past), temporal branching, or non-deterministic settling are out of scope and are a research question, not a milestone claim.
- **Not TAB/qtOps replacement.** M26 proves the predication algebra can reproduce what TAB's merge-models and qtOps's quality-composition do.
  It does not migrate the existing MUD engines; it proves the substrate makes migration unnecessary.
- **Not stratum-4.** The demonstration uses three strata (0/1/2).
  No "observable" fourth stratum exists.
  The MCP surface's behavior is the stratum-2 projection, not a separate stratum.

## Theoretical shape

**Spatial relations as predicate-category morphisms.** Room exits are predicate specializations in the predicate category C.
The predication-fiber-functor theorem establishes that specializations, converses, and projections act on fiber algebras via bilattice homomorphisms.
Navigation is not spatial — it is the predicate-category morphism composition that the theorem guarantees is well-defined and natural.

**State machines as bilattice value sequences.** The Belnap-Fitting FOUR bilattice {⊥, t, f, ⊤} is not an implementation convenience — it is the algebra's natural four-valued truth structure.
State machines whose states are {unknown, open, closed, contradiction} correspond exactly to FOUR. cl^S rules fire value transitions.
N_Δ stabilizes per-cell.
The state machine is the cell's value trajectory under F_U.

**Generation as necessity of the algebra, not design.** The outer alternation — where N_Δ-stabilized stratum-2 atoms satisfy cl^S premises at new coordinates — is mathematically necessary when the rule system has such cross-stratum premises.
The dungeon does not need a generation algorithm; the algebra generates it.
The predication-cell-as-fold-source theorem grounds the uniqueness of each fold-step in the cascade.
