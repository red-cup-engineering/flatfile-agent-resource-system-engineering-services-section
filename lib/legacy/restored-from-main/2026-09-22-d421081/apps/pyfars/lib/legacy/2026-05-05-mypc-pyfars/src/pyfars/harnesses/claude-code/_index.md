Materializes substrate agent records (under [`operations/engineering/agents/`](../../agents/)) as Claude Code subagent definitions that the [Claude Code](https://docs.anthropic.com/claude/docs/claude-code) runtime auto-discovers and dispatches against.

## What it writes

For each `operations/engineering/agents/<slug>.md` (skipping `_index.md` and any directory entries):

```
.claude/agents/<slug>.md
```

with Claude-Code-flavored frontmatter (`name`, `description`, optional `model`) and a body summarizing the agent's role, duties, skills, jurisdiction, and the autonomous-vs-escalate boundary the substrate record declares.

A manifest is written to `.fars/harness-manifests/claude-code.json` recording every projected file and its substrate source, so `--uninstall` is exact.

## What this harness does *not* yet write

The Claude Code runtime also reads:

- `.claude/commands/<slug>.md` — slash-commands. No substrate record-shape exists yet; once
  `operations/engineering/commands/` is populated with command records the projector here
  will be extended.
- `.claude/hooks/` and `.claude/settings.json` — event hooks (e.g. SessionStart). **Now
  handled by the sister harness [`claude-code-hooks`](../claude-code-hooks/_index.md)**,
  which projects substrate records under [`operations/engineering/hooks/`](../../hooks/)
  into Claude Code's hook protocol with bilattice-valued witness emission per event. The
  two harnesses install into the same `.claude/` target and coexist (this one writes
  `.claude/agents/`; the sister writes `.claude/hooks/` and the `hooks` block of
  `.claude/settings.json`).

The repo's root `CLAUDE.md` — Claude Code's project-level system prompt — is generated by the [`repo-instructions`](../repo-instructions/) harness, not this one, because that file is shared with several other consumers (humans reading the repo, the Replit Agent, etc.).

## Why a projection, not a hand-written file

Two consumers writing the "what is this agent" sentence twice is two opportunities to drift. The substrate record is the source of truth (it has model tier, duties, powers, skills, jurisdiction, autonomous-vs-escalates — far more than Claude Code's frontmatter exposes). The projection picks the subset Claude Code's runtime actually consumes and writes it in Claude Code's format. Edit the substrate record, re-run the harness, and the projection updates.

## Frontmatter projection

| Substrate field | `.claude/agents/<slug>.md` field | Notes |
|---|---|---|
| filename stem | `name` | The slug Claude Code dispatches against. |
| `description` | `description` | Truncated to fit the dispatcher. |
| `model` (`opus`/`sonnet`/`haiku`) | `model` | Passed through if present. |
| (other fields) | rendered into the body | Duties, powers, skills, jurisdiction, autonomous/escalates. |

`tools:` is intentionally omitted so each subagent inherits the parent agent's full toolset.
