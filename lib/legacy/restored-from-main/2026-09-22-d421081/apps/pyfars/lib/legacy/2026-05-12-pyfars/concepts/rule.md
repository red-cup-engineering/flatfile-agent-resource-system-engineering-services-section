# Rule

A substrate-recordable [closure-rule](../../../../theories/theories/humanities/theories/math/theories/categories/theories/predication-categories/concepts/closure-rule.md) — the *syntactic generator* of system-side closure operators.
A rule asserts a single conditional cell-update: when an antecedent over system state holds, a particular cell value must rise to at least a particular knowledge-order threshold.

Rule schema (from upstream):

$$\underbrace{\forall x_1 \cdots \forall x_n.\; \phi(\vec{x};\, \vec{y};\, v)}_{\text{positive } \Pi_1 \text{ antecedent}} \;\Longrightarrow\; \underbrace{v'(p)(t_1, t_2) \geq_k V}_{\text{cell-update consequent}}$$

The rule fires *once per $\vec{y}$-instantiation* from the polity's entity space.
The antecedent $\phi$ is drawn from the active [closure-rule-language](../../../../theories/theories/humanities/theories/math/theories/categories/theories/predication-categories/concepts/closure-rule-language.md); the consequent is a cell-update bounding a target cell from below in the knowledge-order $\geq_k$.

## What a rule is, substantively

A rule is *not* a procedure, *not* a Python function in the runtime, *not* a code-defined check.
A rule in the predication-theoretic sense is a *syntactic object* — a pair (antecedent-formula, cell-update-consequent) — interpretable against any system state.

PyFARS realizes rules as system cells: a `kind: rule` record carrying:

1. **Antecedent specification** — the formula $\phi$, in the active rule-language fragment, with its free and bound variables marked.
2. **Consequent specification** — the target cell pattern and the lower-bound value $V$.
3. **Variable binding shape** — which variables are universally bound (range over all entities), which are free (rule fires once per instantiation).
4. **Provenance** — when the rule was enacted, by which authority, under which charter section.
  Rules are themselves substrate; rules can be revoked, amended, audited.

The runtime *interprets* rule cells against system state during [inducing](../morphisms/inducing.md).
A rule is data; the runtime is its interpreter.

## Rule and the rule-language

The [closure-rule-language](../../../../theories/theories/humanities/theories/math/theories/categories/theories/predication-categories/concepts/closure-rule-language.md) specifies what formulas $\phi$ are admissible.
Different fragments — strict, Scott-continuous, transfinite-bounded, aperiodic — produce different closure regimes per the [four-regime dichotomy](../../../../theories/theories/humanities/theories/math/theories/categories/theories/predication-categories/theorems/four-regime-dichotomy.md).

PyFARS's rules are in specific fragments depending on what they do:

- **Frontmatter validation rules** — typically strict (finite predicates, finite entities).
- **Dispatch-readiness rules** — typically Scott-continuous (infinite witness-arrival, finitary antecedents).
- **Governance closure rules** — may climb to transfinite-bounded or aperiodic (charter amendment dynamics, multi-step adjudication).

The rule's language fragment determines the regime its participation contributes to.

## Rule and inducing

A rule generates [inducing](../morphisms/inducing.md) steps: when its antecedent matches, it induces the consequent cell.
Each successful match is one inducing step; iterated inducing under all rules in a [ruleset](ruleset.md) is [settling](../morphisms/settling.md).

A rule does not "fire" in isolation — the closure operator generated by the active ruleset fires; individual rule contributions are factor-able from the closure but the ruleset is what's load-bearing.

## Rule and authority

Authoring a rule is a governance act.
Rules participate in the polity's deontic structure: the captain can [enact](../morphisms/enacting.md) charter-level rules; offices can enact rules within their action-domains; ad-hoc rule-creation by ordinary agents is not permitted.
Rules carry provenance witnesses; revocation is a matched de-enacting witness.

## What this concept does not yet specify

- The complete rule-language schema.
  Currently a hybrid: some rules are substrate-declared (in `_index.md` or governance entries), some are Python-coded in the `pyfars.convention` and `pyfars.analyze` modules.
  The migration toward fully-substrate-declared rules is partly settled.
- Rule-revision semantics.
  When a rule is amended, what happens to cells previously induced under the old rule?
  The reconciliation discipline is partly settled.
- Rule conflicts.
  Two rules whose consequents would induce contradictory cells produce $\top$-valued cells (paraconsistent — surfaced not silently coerced); whether this is permissible by-rule or always-error is a program-shaping question.
